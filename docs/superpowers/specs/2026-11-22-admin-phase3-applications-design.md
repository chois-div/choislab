# 어드민 3단계 설계: 의뢰·지원 현황 (applications)

## 배경
아임웹 전문가 의뢰에 지원한 기록을 지금은 구글 시트("초이스랩 지원 현황", 시트1)에 수기로 적는다. 이를 Supabase로 옮겨 어드민(`/ops/`)에서 조회·수정·분석하고, 매칭된 의뢰는 고객·프로젝트로 전환한다. 2단계 문서(`2026-11-21-admin-phase2-design.md`)의 구조(Supabase 로그인, RLS, `/ops/` 단일 파일 바닐라 JS)를 그대로 따른다.

## 범위
**포함**
- `applications` 테이블과 목록·검색·상태 탭·편집 패널
- 회신·매칭 상태 추적
- 효과 분석(코멘트 형식별·예산대별·경쟁자 수별 회신률)
- 매칭된 의뢰의 프로젝트 전환
- 시트 CSV 일회성 가져오기(중복 방지)

**제외**
- 아임웹 의뢰 목록 자동 수집·자동 지원(브라우저 자동화는 기존 "업데이트" 루틴에서 계속 수행)
- 시트 실시간 동기화. 가져온 뒤 원본은 Supabase이며 시트는 읽기 백업으로 남긴다.
- 지원 시 시트 기록 절차 변경은 별도(어드민 입력으로 대체 가능)

## 데이터 모델
`applications`
| 컬럼 | 타입 | 원본(시트 열) / 비고 |
|---|---|---|
| id | uuid pk | |
| applied_on | date null | 지원일 (미기재 허용) |
| title | text not null | 의뢰명 |
| platform | text | 플랫폼 (기본 imweb) |
| work_type | text | 작업유형 |
| budget_text | text | 예산(만원) 원문 (`500~700`, `협의중` 등) |
| bid_text | text | 내 견적(원문) |
| invoice_need | text | 세금계산서: 필요/미기재/미해당 |
| withholding | text | 3.3% 문의: O/X/- |
| competitors | int null | 경쟁자수 (`2명` → 2) |
| portfolio | text | 포트폴리오 |
| status | text | 지원완료 / 문의중 / 미팅 / 매칭완료 / 불발 |
| contact_status | text | 대기 / 회신대기 / 회신있음 등 (시트 드롭다운 값 그대로) |
| memo | text | 메모 |
| message | text | 지원메시지 |
| experiment | text null | 코멘트 형식 태그 (예: `새 형식`, `기존 형식`). 시트 메모의 "실험(새 형식)" 표기에서 추출 |
| project_id | uuid null | 전환한 프로젝트 (on delete set null) |
| created_at / updated_at | timestamptz | |

제약: 문자열 길이 상한, `status`와 `contact_status`는 위 값 목록으로 check 제약(시트의 실제 드롭다운 값을 확인해 확정), 중복 방지용 unique index `(coalesce(applied_on,'0001-01-01'), title)`.
RLS: `authenticated`만 전체 접근, `anon` 권한 없음(기존 테이블과 동일).

## 화면 (Figma 시안: 지원 현황 / 지원 기록 상세 / 효과 분석 / CSV 가져오기)
- **목록:** KPI 4개(전체 지원, 회신률, 진행 중, 매칭 완료), 상태 탭, 검색(의뢰명·메모), 표(지원일, 의뢰명, 작업유형, 예산, 경쟁, 상태, 연락, 실험), 더 보기.
- **상세 슬라이드 패널:** 모든 필드, 상태 변경 세그먼트, 지원 메시지, 메모, 수정, "프로젝트로 전환 →".
- **효과 분석:** 기간(최근 30일/전체) 선택, 코멘트 형식별 비교 표, 예산대별·경쟁자 수별 회신률 막대. 표본이 작으면 안내 문구를 표시한다.
- **CSV 가져오기:** 파일 선택 → 파싱 → 가져올 수 있음/확인 필요/중복 건수 요약, 미리보기 5건, 경고 목록 → 실행.

## 규칙
- **회신 정의:** `contact_status`가 `회신있음` 이상(문의중·미팅·매칭완료 포함)이면 회신으로 센다. 분모는 해당 기간의 전체 지원 수.
- **예산대 구간:** `budget_text`에서 첫 숫자를 읽어 50 이하 / 50~150 / 150 이상, 숫자가 없으면 협의·미정으로 분류한다.
- **프로젝트 전환:** DB 함수 `convert_application_to_project(id)` — 고객(의뢰명 기준 신규 생성), 프로젝트(단계: 견적), 예산·세금 정보를 프로젝트 메모로 복사, `applications.project_id` 연결. 이미 전환되었으면 기존 프로젝트 id를 반환한다. 전체가 하나의 트랜잭션.
- **CSV 가져오기:** 클라이언트에서 파싱(따옴표·줄바꿈 포함 필드 지원), 헤더 이름으로 열을 매핑, 값은 모두 텍스트로만 다룬다. 서버 전달은 `on_conflict` ignore로 중복 건을 건너뛴다. 날짜 형식은 `YYYY-MM-DD`/`YYYY.MM.DD`/`YYYY/MM/DD`만 허용하고 나머지는 지원일 비움 + 경고.
- 화면에 표시하는 모든 사용자 데이터는 텍스트로만 삽입한다(HTML 삽입 금지).

## 오류 처리
저장 실패 시 패널을 닫지 않고 입력을 유지한다. 가져오기는 변환 오류 행을 건너뛰고 경고로 보여 준다. 전환 실패 시 아무것도 만들어지지 않는다.

## 테스트
임시 가짜 DB로 목록·필터·검색·상태 변경·분석 계산·전환·가져오기(중복 재가져오기 포함)를 브라우저에서 확인하고, DB 함수는 시험 행으로 검증한 뒤 지운다. 실제 시트 CSV는 사용자가 직접 올려 확인한다.

## 사용자가 할 일
시트를 CSV로 내려받아 가져오기 화면에서 올린다(시트 접근 제한으로 에이전트가 직접 읽을 수 없음). 상태·연락여부의 실제 드롭다운 값 목록을 확인해야 하므로 가져오기 첫 실행 시 표시되는 "알 수 없는 값" 경고로 보완한다.
