# 초이스랩 어드민 2단계 설계 (고객·프로젝트·문의 관리, Supabase 기반)

## 배경

초이스랩 운영 도구는 흩어져 있다: `/admin/`(Sveltia CMS, 포트폴리오), `/quote/`(견적서 작성, Google Apps Script + 시트 저장), `contract-docket/`(전자계약, 미배포). 1단계는 이미 승인된 `docs/superpowers/specs/2026-11-15-ops-dashboard-design.md`의 `/ops/` 요약 대시보드(기존 비밀번호 방식)를 그대로 구현한다. 이 문서는 그 위에 얹는 **2단계**를 다룬다.

사용자 요구: 견적서, 고객·프로젝트, 의뢰·지원 현황을 모두 관리하는 어드민. 비용은 무료 범위를 유지한다.

## 단계 구분

| 단계 | 내용 | 문서 |
|---|---|---|
| 1 | `/ops/` 요약 대시보드 (기존 비밀번호, 포트폴리오/견적서/아임웹 문의/계약 준비중 카드) | 기존 스펙·플랜 그대로 |
| **2** | **Supabase 도입, 로그인 전환, 견적서 이전, 고객·프로젝트·입금·세금 관리, 홈페이지 문의 폼·문의함** | **이 문서** |
| 3 | 의뢰·지원 현황 (아임웹 지원 기록, 회신·매칭) | 별도 스펙 |

2단계에서 Apps Script 비밀번호 방식을 은퇴시키고 Supabase 이메일+비밀번호 로그인으로 통일한다.

## 범위

**포함**
- Supabase 프로젝트(무료 플랜) 기반 구축: Auth, 테이블, RLS
- `/ops/` 로그인을 Supabase 이메일+비밀번호로 전환, `/quote/`와 세션 공유
- 견적서 시트 → Supabase 일회성 임포트, `/quote/` 저장·목록·불러오기 교체
- 고객, 프로젝트, 입금, 세금 처리 관리 화면
- 홈페이지 문의 폼(신규)과 문의함, 문의 → 프로젝트 전환
- 대시보드 상단 요약(이번 주 마감, 미수금 합계, 세금계산서 미발행 건수, 신규 문의 수)

**제외**
- 푸시·이메일 알림 발송 (대시보드에서 눈으로 확인하는 수준)
- 의뢰·지원 현황 (3단계)
- `contract-docket` 실배포 및 전자계약 연동
- 아임웹 방문자/트래픽 통계 (공식 API에 없음)

## 아키텍처

```
choislab (GitHub Pages, 정적, 빌드 도구 없음)
├── /index.html  홈페이지. 문의 폼 신규 추가 (비로그인 INSERT 전용)
├── /ops/        어드민. Supabase 로그인 + 좌측 메뉴
├── /quote/      견적서 작성. 저장소를 Supabase로 교체
└── /admin/      포트폴리오 CMS (변경 없음)

Supabase (무료 플랜)
├── Auth        본인 계정 1개, 외부 가입 비활성화
├── 테이블      customers, projects, payments, invoices, quotes, inquiries
└── RLS         본인 계정만 읽기·쓰기. inquiries만 비로그인 INSERT 허용

ops-api (Render, 1단계에서 생성)
└── 아임웹 문의 카드 전용. 요청 검증을 Apps Script ping에서 Supabase 토큰 검증으로 교체
```

- 화면은 Supabase 공개(anon) 키로 직접 조회·저장한다. 공개 키가 노출되어도 RLS가 데이터를 보호하므로 중간 서버는 두지 않는다.
- `/ops/`와 `/quote/`는 같은 Supabase 세션을 공유한다. 미로그인 상태에서는 로그인 창만 보인다.
- `/ops/`는 기존 방침대로 `robots.txt` 차단과 `noindex`를 유지한다.

## 데이터 모델

```
customers      id, 이름, 담당자, 연락처, 이메일, 유입 경로(아임웹/지인/홈페이지 등), 메모
projects       id, customer_id, 프로젝트명, 단계, 착수일, 마감일, 계약금액, 메모, quote_doc_no
payments       id, project_id, 구분(선금/중도금/잔금), 금액, 입금 예정일, 실제 입금일
invoices       id, project_id, 구분(세금계산서/3.3% 원천징수), 금액, 발행일, 발행 여부
quotes         doc_no(PK), project_id(nullable), 고객명, 프로젝트명, 금액, 상태, data(jsonb)
inquiries      id, 이름, 연락처, 문의 유형, 예산대, 내용, 개인정보 동의 시각, 상태, created_at, project_id(nullable)
```

- 프로젝트 단계: 문의 → 견적 → 계약 → 제작 → 검수 → 완료, 별도로 보류.
- 문의 상태: 신규, 확인, 답변 완료, 보류.
- 미수금 = 계약금액 − 실제 입금 합계 (조회 시 계산, 저장하지 않음).
- `quotes.data`에는 기존 `/quote/`가 저장하던 상세 필드를 그대로 보관한다.
- `inquiries` 정책: 비로그인 INSERT만 허용(SELECT, UPDATE, DELETE 불가). 글자 수 제한과 필수값은 DB 제약으로 건다.

## 화면

- **로그인:** 이메일+비밀번호. 세션 만료 시 입력 중인 내용을 유지한 채 로그인 창을 띄운다.
- **대시보드:** 상단 요약(이번 주 마감, 미수금 합계, 세금계산서 미발행 건수, 신규 문의 수) + 1단계의 포트폴리오·견적서·아임웹 문의·계약(준비중) 카드.
- **프로젝트 목록:** 단계별로 모아 보고, 마감 7일 이내와 미수금 있는 건을 강조.
- **프로젝트 상세:** 단계, 일정, 입금 내역, 세금 처리, 연결된 견적서를 한 화면에.
- **고객 목록·상세:** 고객 정보와 프로젝트 이력.
- **문의함:** 상태별 목록과 상세. 상세에서 "프로젝트로 전환"을 누르면 고객과 프로젝트(단계: 문의)를 생성하고 `inquiries.project_id`를 연결한다.
- **견적서 메뉴:** 새 화면 없이 요약을 표시하고 `/quote/`로 연결한다 (`/quote/` UI는 이미 있다).

## 홈페이지 문의 폼

- 항목: 이름, 연락처(이메일 또는 전화), 문의 유형, 예산대, 문의 내용, 개인정보 수집 동의(필수, 기존 `/privacy`로 연결).
- 저장: Supabase `inquiries`에 공개 키로 직접 INSERT.
- 스팸 방지: 숨김 입력칸(허니팟), 글자 수 제한. 부족하면 Cloudflare Turnstile(무료)을 추가한다.
- 기존 `mailto:` 링크는 유지한다.

## 견적서 이전

1. 시트의 기존 견적을 JSON으로 내보낸다.
2. 임포트 스크립트로 `quotes`에 한 번 넣고, 건수와 합계 금액을 시트와 대조한다.
3. `/quote/`의 저장·목록·불러오기를 Supabase로 교체한다.
4. 확인 후 Apps Script는 읽기 전용 백업으로 두고 쓰기를 막는다. 문제 시 이전 `quote/index.html`로 되돌린다.

## 오류 처리

- 카드·목록 단위로 조회가 실패하면 해당 영역만 "불러오기 실패", 나머지는 정상 동작.
- 입금 합계가 계약금액을 넘으면 경고만 표시하고 저장은 허용(추가 작업 가능성).
- 문의 폼 저장 실패 시 입력 내용을 유지하고 이메일 문의 링크를 안내한다.
- 임포트는 대조가 어긋나면 중단하고, 이미 들어간 데이터는 `doc_no` 기준으로 재실행해도 중복되지 않게(upsert) 한다.

## 테스트 방법 (브라우저 확인, 별도 자동화 프레임워크 없음)

- 미로그인 상태에서 `/ops/`·`/quote/`에 데이터가 보이지 않는지
- 공개 키로 `quotes`, `customers`, `projects` 등을 직접 SELECT할 때 거부되는지, `inquiries`는 INSERT만 되고 SELECT는 거부되는지
- 임포트 후 견적 건수와 금액이 시트와 일치하는지
- 미수금과 마감 임박 계산이 맞는지
- 한 영역 조회 실패 시 나머지가 동작하는지
- 문의 폼 제출 → 문의함 표시 → 프로젝트 전환까지 한 흐름으로 동작하는지
- `/ops/`가 검색엔진에 노출되지 않는지

## 구현 전 사용자가 직접 할 일

- Supabase 계정·프로젝트 생성(무료), 본인 로그인 계정 1개 생성, 외부 가입(sign-ups) 비활성화
- 프로젝트 URL과 공개(anon) 키 전달 (service_role 키는 전달·저장하지 않는다)
- 시트의 기존 견적 내보내기는 구현 단계에서 함께 진행

## 위험과 한계

- Supabase 무료 플랜은 장기간 미사용 시 프로젝트가 일시정지될 수 있다. 대시보드를 주기적으로 열면 예방된다.
- 문의 알림이 없어 새 문의를 놓칠 수 있다. 필요해지면 Supabase 기능으로 이메일 알림을 후속 추가한다.
- 1인 사용 전제로 설계했다. 다중 사용자·권한 분리는 범위 밖이다.
