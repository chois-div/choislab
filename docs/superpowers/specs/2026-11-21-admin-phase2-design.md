# 초이스랩 어드민 2단계 설계 (고객·프로젝트·문의 관리, Supabase 기반)

## 배경

초이스랩 운영 도구는 흩어져 있다: `/admin/`(Sveltia CMS, 포트폴리오), `/quote/`(견적서 작성, Google Apps Script + 시트 저장), `contract-docket/`(전자계약, 미배포). 1단계는 이미 승인된 `docs/superpowers/specs/2026-11-15-ops-dashboard-design.md`의 `/ops/` 요약 대시보드(기존 비밀번호 방식)를 그대로 구현한다. 이 문서는 그 위에 얹는 **2단계**를 다룬다.

사용자 요구: 견적서, 고객·프로젝트, 의뢰·지원 현황을 모두 관리하는 어드민. 비용은 무료 범위를 유지한다.

## 단계 구분

| 단계 | 내용 | 문서 |
|---|---|---|
| 1 | `/ops/` 요약 대시보드 (기존 비밀번호, 포트폴리오/견적서/아임웹 문의/계약 준비중 카드) | 기존 스펙·플랜 그대로 |
| **2** | **Supabase 도입, 로그인 전환, 견적서 이전, 고객·프로젝트·입금·세금 관리, 홈페이지 문의 폼·문의함** | **이 문서** |
| 3 | 의뢰·지원 현황 (아임웹 지원 기록, 회신·매칭) | 별도 스펙 |

2단계에서 Apps Script 비밀번호 방식을 은퇴시키고 Supabase 이메일+비밀번호 로그인으로 통일한다.

## 범위

**포함**
- Supabase 프로젝트(무료 플랜) 기반 구축: Auth, 테이블, RLS
- `/ops/` 로그인을 Supabase 이메일+비밀번호로 전환, `/quote/`와 세션 공유
- 견적서 시트 → Supabase 일회성 임포트, `/quote/` 저장·목록·불러오기 교체
- 고객, 프로젝트, 입금, 세금 처리 관리 화면
- 홈페이지 문의 폼(신규)과 문의함, 문의 → 프로젝트 전환
- 대시보드 상단 요약(이번 주 마감, 미수금 합계, 세금계산서 미발행 건수, 신규 문의 수, 플랜 만료 임박 건수)
- 입력·수정 화면: 프로젝트, 고객, 입금, 세금 항목, 플랜 정보를 하나의 공통 슬라이드 패널 형식으로 수기 입력
- 플랜 만료 관리: 아임웹·프레이머 플랜 결제·만료일은 수기 입력하고, 만료 30일 이내를 대시보드와 프로젝트 목록에 표시
- 우선 기능 A·B: 새 문의 이메일 알림, 견적 확정 → 프로젝트·입금 일정 자동 생성 (아래 "우선 구현 기능")

**제외**
- 플랜 결제·만료일 자동 수집: 프레이머는 공개 API가 없고, 아임웹은 사이트 정보 API의 응답 항목을 확인하지 못했다. 고객 계정 결제분은 접근 권한도 없다. 수기 입력으로 시작하고, 아임웹 API에 만료일이 있는 것으로 확인되면 해당 필드만 자동 채움으로 전환한다.
- 푸시·이메일 알림 발송 (대시보드에서 눈으로 확인하는 수준)
- 의뢰·지원 현황 (3단계)
- `contract-docket` 실배포 및 전자계약 연동
- 아임웹 방문자/트래픽 통계 (공식 API에 없음)

## 우선 구현 기능

2단계 안에서 아래 두 기능을 먼저 만든다. A는 문의 폼·문의함만 있으면 되고, B는 견적서가 Supabase로 이전된 뒤에 가능하다.

### A. 새 문의 이메일 알림
- 트리거: 접수 Edge Function(`submit-inquiry`)이 문의를 저장한 직후 이메일 발송 서비스(무료 플랜, 예: Resend)로 보낸다. 별도 Database Webhook은 두지 않는다.
- 수신: choislab.studio@gmail.com 1개. Edge Function 시크릿에 저장하고 화면 설정은 두지 않는다.
- 내용: 이름, 문의 유형, 예산대, 문의 내용 앞 100자, 문의함 링크. 연락처와 첨부 파일은 개인정보 최소화를 위해 메일에 넣지 않는다.
- 실패 처리: 알림 실패는 문의 저장에 영향을 주지 않는다. 문의는 항상 저장되고 대시보드 "신규 문의"에 표시된다. 실패는 Edge Function 로그로 확인한다.
- 남용 방지: Turnstile을 통과한 제출만 저장되고, 시간당 알림 20통을 넘으면 초과분의 알림만 생략한다(문의는 저장).

### B. 견적 확정 → 프로젝트 자동 생성
- `/quote/`에 "확정하고 프로젝트 만들기" 버튼을 둔다. 누르면 확인 창에서 만들어질 내용을 미리 보여 주고, 확정하면 다음을 한 번에 처리한다.
  1. 견적 상태를 "확정"으로 변경
  2. 고객: 같은 이름의 기존 고객이 있으면 자동 선택하고, 없으면 "새 고객으로 생성". 확인 창에서 다른 고객으로 바꿀 수 있다.
  3. 프로젝트: 프로젝트명·계약금액을 견적에서 복사, 단계는 "계약", `quote_doc_no`로 견적과 연결
  4. 입금 일정: 기본 선금 40% / 중도금 30% / 잔금 30%. 확인 창에서 비율을 조정할 수 있고, 금액은 계약금액 기준으로 계산한다(반올림 차이는 마지막 항목이 흡수).
  5. 입금 예정일, 착수일, 마감일은 비워 두고 프로젝트 상세에서 입력한다.
- 중복 방지: 이미 프로젝트가 연결된 견적에는 버튼 대신 "프로젝트 보기"를 보여 준다.
- 원자성: 1~4는 하나의 DB 함수(트랜잭션)로 처리해, 중간에 실패하면 아무것도 만들어지지 않는다.
- 비율 합계가 100%가 아니면 확정 버튼을 비활성화한다.

## 아키텍처

```
choislab (GitHub Pages, 정적, 빌드 도구 없음)
├── /index.html  홈페이지. 문의 폼 신규 추가 (비로그인 INSERT 전용)
├── /ops/        어드민. Supabase 로그인 + 좌측 메뉴
├── /quote/      견적서 작성. 저장소를 Supabase로 교체
└── /admin/      포트폴리오 CMS (변경 없음)

Supabase (무료 플랜)
├── Auth        본인 계정 1개, 외부 가입 비활성화
├── 테이블      customers, projects, payments, invoices, quotes, inquiries
├── RLS         본인 계정만 읽기·쓰기. 비로그인(anon)에는 정책 없음
└── Edge Function  submit-inquiry: 홈페이지 문의 접수 전용 (Turnstile 검증, 저장, 업로드 URL 발급, 알림 메일)

ops-api (Render, 1단계에서 생성)
└── 아임웹 문의 카드 전용. 요청 검증을 Apps Script ping에서 Supabase 토큰 검증으로 교체
```

- 화면은 Supabase 공개(anon) 키로 직접 조회·저장한다. 공개 키가 노출되어도 RLS가 데이터를 보호하므로 중간 서버는 두지 않는다.
- `/ops/`와 `/quote/`는 같은 Supabase 세션을 공유한다. 미로그인 상태에서는 로그인 창만 보인다.
- `/ops/`는 기존 방침대로 `robots.txt` 차단과 `noindex`를 유지한다.

## 데이터 모델

```
customers      id, 이름, 담당자, 연락처, 이메일, 유입 경로(아임웹/지인/홈페이지 등), 메모
projects       id, customer_id, 프로젝트명, 단계, 착수일, 마감일, 계약금액, 메모, quote_doc_no,
               플랫폼(아임웹/프레이머/기타), 플랜명, 플랜 결제 주체(본인/고객), 플랜 결제일, 플랜 만료일, 자동 갱신 여부
payments       id, project_id, 구분(선금/중도금/잔금), 금액, 입금 예정일, 실제 입금일
invoices       id, project_id, 구분(세금계산서/3.3% 원천징수), 금액, 발행일, 발행 여부
quotes         doc_no(PK), project_id(nullable), 고객명, 프로젝트명, 금액, 상태, data(jsonb)
inquiries      id, 이름, 연락처, 문의 유형, 예산대, 플랫폼 선호, 희망 오픈일, 기존 사이트 URL, 참고 URL(최대 3개), 내용,
               개인정보 동의 시각, 상태, created_at, project_id(nullable)
inquiry_files  id, inquiry_id, 저장 경로, 원본 파일명, 크기, 형식
```

- 프로젝트 단계: 문의 → 견적 → 계약 → 제작 → 검수 → 완료, 별도로 보류.
- 문의 상태: 신규, 확인, 답변 완료, 보류.
- 미수금 = 계약금액 − 실제 입금 합계 (조회 시 계산, 저장하지 않음).
- `quotes.data`에는 기존 `/quote/`가 저장하던 상세 필드를 그대로 보관한다.
- `inquiries`, `inquiry_files` 정책: 로그인한 본인 계정만 읽기·수정. 비로그인(anon)에는 어떤 정책도 두지 않는다(접수는 Edge Function이 서비스 키로 처리). 글자 수 제한과 필수값은 DB 제약으로도 건다.

## 화면

- **로그인:** 이메일+비밀번호. 세션 만료 시 입력 중인 내용을 유지한 채 로그인 창을 띄운다.
- **대시보드:** 상단 요약(이번 주 마감, 미수금 합계, 세금계산서 미발행 건수, 신규 문의 수) + 1단계의 포트폴리오·견적서·아임웹 문의·계약(준비중) 카드.
- **프로젝트 목록:** 단계별로 모아 보고, 마감 7일 이내와 미수금 있는 건을 강조.
- **프로젝트 상세:** 단계, 일정, 입금 내역, 세금 처리, 연결된 견적서를 한 화면에.
- **고객 목록·상세:** 고객 정보와 프로젝트 이력.
- **문의함:** 상태별 목록과 상세. 상세에서 "프로젝트로 전환"을 누르면 고객과 프로젝트(단계: 문의)를 생성하고 `inquiries.project_id`를 연결한다.
- **입력·수정 패널:** 화면 오른쪽에서 열리는 공통 슬라이드 패널. 프로젝트(플랫폼·플랜 정보 포함), 고객, 입금, 세금 항목이 같은 형식(라벨 + 입력칸, 하단 취소/저장)을 쓴다. 저장 실패 시 패널을 닫지 않고 입력 내용을 유지한다. 문의는 상태 변경과 프로젝트 전환만 하고 내용은 수정하지 않는다.
- **플랜 카드(프로젝트 상세):** 플랫폼, 플랜명, 결제 주체, 결제일, 만료일(D-day)을 표시한다.
- **견적서 메뉴:** 새 화면 없이 요약을 표시하고 `/quote/`로 연결한다 (`/quote/` UI는 이미 있다).

## 홈페이지 문의 폼

- 위치: 홈페이지 맨 아래 CTA 섹션(`id="contact"`). 가격표의 "시작하기/상담 받기" 버튼이 이미 `#contact`로 연결돼 있다. 이메일·카카오 채널 버튼은 폼 옆에 유지한다.
- 필수 항목: 이름, 연락처(이메일 또는 전화), 문의 유형, 문의 내용, 개인정보 수집 동의(기존 `/privacy`로 연결).
- 제작에 필요한 선택 항목: 예산대, 플랫폼 선호(아임웹/프레이머/잘 모르겠어요), 희망 오픈일, 기존 사이트 URL(리뉴얼인 경우), 참고 URL(최대 3개), 기획안·참고 자료 첨부.
- 첨부 파일: 최대 3개, 개당 10MB, 형식은 PDF·이미지(PNG/JPG)·PPT·문서(DOC/HWP)·엑셀로 제한한다. 비공개 Storage 버킷에 저장하고, 비로그인 방문자는 업로드만 가능하며 열람은 로그인한 본인만 가능하다(서명 URL). 형식·용량 제한은 버킷 설정으로 서버에서도 강제한다.
- URL 입력은 `http(s)://`만 허용하고, 문의함에서 링크를 열 때는 새 탭(noopener)으로 연다.
- 접수 경로: 방문자 브라우저는 DB·Storage에 직접 접근하지 않고, Edge Function `submit-inquiry` 하나만 호출한다. 함수가 입력을 검증하고, Turnstile 토큰을 서버에서 확인한 뒤, 서비스 키로 `inquiries`와 `inquiry_files`에 저장하고, 첨부 파일용 서명된 업로드 URL(최대 3개)을 돌려준다. 브라우저는 그 URL로 파일을 올린다.
- 스팸 방지: 숨김 입력칸(허니팟), 글자 수 제한, Cloudflare Turnstile(무료)을 함수에서 검증한다. 직접 INSERT를 허용하면 Turnstile 검증을 우회할 수 있으므로 비로그인 접근은 전부 막는다.
- 기존 `mailto:` 링크는 유지한다.

## 견적서 이전

1. 시트의 기존 견적을 JSON으로 내보낸다.
2. 임포트 스크립트로 `quotes`에 한 번 넣고, 건수와 합계 금액을 시트와 대조한다.
3. `/quote/`의 저장·목록·불러오기를 Supabase로 교체한다.
4. 확인 후 Apps Script는 읽기 전용 백업으로 두고 쓰기를 막는다. 문제 시 이전 `quote/index.html`로 되돌린다.

## 오류 처리

- 카드·목록 단위로 조회가 실패하면 해당 영역만 "불러오기 실패", 나머지는 정상 동작.
- 입금 합계가 계약금액을 넘으면 경고만 표시하고 저장은 허용(추가 작업 가능성).
- 문의 폼 저장 실패 시 입력 내용을 유지하고 이메일 문의 링크를 안내한다.
- 임포트는 대조가 어긋나면 중단하고, 이미 들어간 데이터는 `doc_no` 기준으로 재실행해도 중복되지 않게(upsert) 한다.

## 테스트 방법 (브라우저 확인, 별도 자동화 프레임워크 없음)

- 미로그인 상태에서 `/ops/`·`/quote/`에 데이터가 보이지 않는지
- 공개 키로 `quotes`, `customers`, `projects`, `inquiries` 등을 직접 SELECT·INSERT할 때 모두 거부되는지, Turnstile 토큰 없이 `submit-inquiry`를 호출하면 거부되는지
- 임포트 후 견적 건수와 금액이 시트와 일치하는지
- 미수금과 마감 임박 계산이 맞는지
- 한 영역 조회 실패 시 나머지가 동작하는지
- 문의 폼 제출 → 문의함 표시 → 프로젝트 전환까지 한 흐름으로 동작하는지
- 첨부: 허용 형식·용량 초과 파일이 거부되는지, 비로그인 상태로 업로드된 파일을 직접 열 수 없는지, 로그인 후 문의함에서만 열리는지
- 참고 URL에 `javascript:` 같은 값이 거부되는지
- 알림: 문의 제출 후 메일이 오는지, 메일에 연락처·첨부가 없는지, 메일 발송을 일부러 실패시켜도 문의가 저장되는지
- 견적 확정: 확인 창 미리보기와 생성 결과가 일치하는지, 같은 견적을 두 번 확정해도 프로젝트가 하나만 생기는지, 중간 실패 시 고객·프로젝트·입금이 하나도 남지 않는지
- `/ops/`가 검색엔진에 노출되지 않는지

## 구현 전 사용자가 직접 할 일

- Supabase 계정·프로젝트 생성(무료), 본인 로그인 계정 1개 생성, 외부 가입(sign-ups) 비활성화
- 프로젝트 URL과 공개(anon) 키 전달 (service_role 키는 전달·저장하지 않는다)
- 시트의 기존 견적 내보내기는 구현 단계에서 함께 진행

## 위험과 한계

- Supabase 무료 플랜은 장기간 미사용 시 프로젝트가 일시정지될 수 있다. 대시보드를 주기적으로 열면 예방된다.
- 파일 업로드는 스팸이나 용량 소진에 노출된다(무료 Storage 1GB). Turnstile, 개수·용량 제한, 처리 끝난 문의 첨부의 주기적 정리로 대응한다.
- 문의 알림이 없어 새 문의를 놓칠 수 있다. 필요해지면 Supabase 기능으로 이메일 알림을 후속 추가한다.
- 1인 사용 전제로 설계했다. 다중 사용자·권한 분리는 범위 밖이다.
